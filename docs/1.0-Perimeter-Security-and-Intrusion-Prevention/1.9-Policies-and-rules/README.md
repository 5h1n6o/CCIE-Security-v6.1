# 1.9-Policies-and-rules

Cisco ASAとCisco FTDにおけるトラフィック制御のためのポリシーとルールの比較表を、提供されたソースに基づき作成しました。

### **Cisco ASA vs Cisco FTD：トラフィック制御の比較表**

| 特徴・項目 | Cisco ASA | Cisco FTD (Firepower Threat Defense) |
| :--- | :--- | :--- |
| **中心となる制御機構** | **アクセスコントロールリスト (ACL)** | **アクセスコントロールポリシー (ACP)** |
| **高度な機能の適用** | **Modular Policy Framework (MPF)** を使用してインスペクションやQoSを適用 | ACP内でAVC、URLフィルタリング、IPS、AMPを**統合的に管理** |
| **デフォルトの動作** | **セキュリティレベル**に基づき、高→低は許可、低→高は拒否される | **ゾーンベース**のポリシー。デフォルトでは全トラフィックが拒否され、明示的な許可が必要 |
| **トラフィック識別** | 主に「5タプル」（送信元/宛先IP・ポート、プロトコル） | 5タプルに加え、アプリケーション、URLカテゴリ、ユーザID、位置情報等 |
| **ルールの処理順序** | ACLエントリを上から順に評価（First-match） | 統合されたポリシーを順序に従って評価（Prefilter -> SI -> ACP等） |
| **主なアクション** | Permit（許可）、Deny（拒否） | Allow, Trust, Monitor, Block, Interactive Block |
| **早期ドロップ機能** | 基本的なACLによるフィルタリング | **Security Intelligence (SI)** や **Prefilter Policy** による早期遮断 |
| **管理ツール** | CLI, ASDM（オンボックス）, FMC（モジュール管理用） | **FMC (推奨)**, FDM（小規模環境向けのWeb GUI） |
| **インスペクションの有効化** | `inspect`コマンドを含むサービスポリシーを適用 | ACPルール内でIntrusion PolicyやFile Policyを直接指定 |

### **主な相違点の詳細**

1.  **設計モデルの転換**:
    *   **ASA**はインターフェイスに設定された「セキュリティレベル」という概念に依存しており、インターフェイス間を通るトラフィック（Through-the-box）の基本フローが自動的に決まります。
    *   **FTD**は「セキュリティゾーン」モデルを採用しており、ASAのようなセキュリティレベルによる自動許可はありません。すべての通信はポリシーで明示的に定義する必要があります。

2.  **インスペクションの実装方法**:
    *   **ASA**で高度な検査（HTTPやFTPの詳細解析）を行うには、MPFを使用してクラスマップとポリシーマップを定義し、サービスポリシーとして適用する手順が必要です。
    *   **FTD**では、単一のACPルールの中で、許可（Allow）したトラフィックに対してIPS（侵入防御）やAMP（マルウェア防御）のインスペクションを直接有効にすることができます。

3.  **アクションの柔軟性**:
    *   **FTD**には「Trust」アクションがあり、これを適用するとSnortエンジンによる深いインスペクションをスキップして高速にパケットを通過させることができます。また、「Interactive Block」により、Webブラウザ上で警告を表示し、ユーザの判断で一時的にブロックを解除させることも可能です。

4.  **処理シーケンスの統合**:
    *   **FTD**は、パケットがデバイスに入力されてから出力されるまでのプロセス（LINAエンジンとSnortエンジン）が統合されています。具体的には、ACPのルール評価前に、Prefilter PolicyやSecurity Intelligence（評判ベースの遮断）といった複数の層でトラフィックを制御します。
